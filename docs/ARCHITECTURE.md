# Архитектура TIA SCL Studio

## Границы решения

```text
TiaSclStudio.App (WPF, x64)
├── TiaSclStudio.Core
├── TiaSclStudio.Diagram ──→ Core
├── TiaSclStudio.Openness
└── TiaSclStudio.Openness.Legacy.V17 ──→ Openness + Siemens API V17

TiaSclStudio.SelfTest ──→ Core + Diagram + Openness
```

- `Core` хранит модель блоков и генерирует внешние SCL-источники. Он не знает о WPF и Siemens API.
- `Diagram` хранит листы, визуальные области, узлы, пины и провода, валидирует граф и превращает лист вызовов в SCL. Он не знает о WPF и Siemens API.
- `App` отображает библиотеку, канву, диагностику, SCL и явный двухфазный Online workflow.
- `Openness` обнаруживает установленные API и содержит DTO/контракт без Siemens-типов.
- `Openness.Legacy.V17` — реальный адаптер V17–V20, который компилируется против
  официального façade API V17. При отсутствии DLL тот же проект выдаёт offline-заглушку.

Все сохраняемые сущности имеют стабильные `Guid`. Связи используют ID, а не изменяемые имена.

## Совместимость TIA Portal

У Openness есть две несовместимые семьи API:

| Семейство | Версии | Сборки | Стратегия |
|---|---|---|---|
| Legacy | V17–V20 | `Siemens.Engineering.dll` | отдельный x64-адаптер на общем API V17 |
| Modular | V21+ | `Siemens.Engineering.Base.dll` и тематические сборки | отдельный x64-адаптер V21+ |

TIA Portal V20 поставляет legacy-сборки V17, V18, V19 и V20. Siemens указывает, что приложения, собранные на этих API, запускаются с V20 без изменения. В V21 архитектура стала модульной, а legacy-сборки V17–V20 больше не поставляются, поэтому V21 нельзя поддержать обычным binding redirect.

Текущий milestone использует один выделенный MTA-поток внутри WPF-процесса:

```text
WPF App
  │  DTO / очередь команд
  ▼
long-lived MTA worker, net48, x64
  │  Siemens.Engineering V17, один installation root на AppDomain
  ▼
TIA Portal
```

Siemens-типы не пересекают публичный контракт. Выбор версии всегда явный: расширение
`.apNN` должно совпадать с Portal VNN, автоматический upgrade запрещён. Legacy façade
нельзя выгрузить из `AppDomain`, поэтому после первой реальной активации смена корня Portal
требует перезапуска. Следующий этап изоляции — перенести тот же DTO-контракт в отдельный
процесс, чтобы независимо загружать разные runtime и переживать fatal-сбой Siemens API.

Текущий статус:

| Версия | Обнаружение | Выгрузка | Покрытие проверки |
|---|---|---|---|
| V17 | реализовано | общий legacy-адаптер реализован | нужна VM/машина V17 и live-test |
| V18 | реализовано | общий legacy-адаптер реализован | нужна VM/машина V18 и live-test |
| V19 | реализовано | общий legacy-адаптер реализован | нужна VM/машина V19 и live-test |
| V20 | проверено локально | live smoke V20 Update 4 пройден через API V17 | один тестовый `.ap20`; это не межверсионная сертификация |
| V21+ | реализован новый layout | запланирован отдельный адаптер | нужна VM/машина V21 |

Зафиксированный live smoke V20 Update 4 подтвердил фактический изменяющий путь:

- приложение подключилось к уже запущенному TIA Portal; read-only dry-run выдал
  одноразовый confirmation token, который был принят перед выгрузкой;
- под `ExclusiveAccess` состояние было проверено повторно, после чего изменения прошли
  одной `Transaction` и были зафиксированы;
- импортированы ровно три SCL-источника; в `Program blocks` созданы `FB_Valve`,
  `FC_CallUnits` и экземплярный DB `V01`;
- последующая компиляция PLC завершилась с 0 ошибками и 0 предупреждениями;
- OB1 остался без изменений;
- в отдельном предшествующем прогоне ошибка импорта не закоммитила транзакцию и не
  оставила частично созданные блоки. Это наблюдение подтверждает rollback именно для
  проверенного сценария отказа, а не для всех возможных сбоев Siemens API.

После smoke остаются обязательные проверки:

- ручной Save проекта с последующим закрытием и повторным открытием;
- повторная выгрузка и принятие сценария перезаписи собственных блоков;
- readback созданной таблицы тегов и её содержимого;
- отдельная live-матрица V17, V18 и V19.

## Генерация проекта и листов вызовов

1. `DiagramProjectCompiler` проверяет Plant и все листы одним fail-closed проходом: глобальные
   символы, стабильные GUID, межлистовые коллизии DB и локальные ошибки графа.
2. Проверяются существование концов провода, направления, единственный провод на входе и
   точное совпадение типов; `InOut` требует writable tag.
3. Алгоритм Кана строит порядок FB/FC и логических узлов. Ручной порядок влияет только на
   одновременно готовые узлы и не может нарушить зависимости.
4. Прямой выход FB/FC в один тег генерируется как `Output => "Tag"`.
5. Выход, используемый другим узлом или несколькими потребителями, получает одну
   `VAR_TEMP`; источник не вычисляется повторно.
6. AND/OR/NOT и сравнения `>`, `<`, `=` сворачиваются в полностью скобочные выражения.
   Прямой `Logic → Tag` создаёт присваивание, fan-out вычисляет результат один раз.
7. Цикл является ошибкой. Автоматического разрыва через память предыдущего цикла нет,
   поскольку это меняет PLC-семантику.
8. Общий пакет содержит Plant-источники один раз и результаты всех листов в порядке
   UDT → FB/FC → все instance DB → все call block → все call-block DB. Любая ошибка очищает
   пакет и не допускает dry-run/экспорт.
9. `DiagramGroup` хранит только визуальную иерархию и прямое членство узлов. Области не
   участвуют в топологии и не создают `REGION` в SCL, поэтому их переименование,
   перемещение, вложение и расформирование не меняют generated source bundle.

В первом срезе разрешены только точные совпадения типов без неявных преобразований.
Конвертирующие узлы будут добавлены явно отдельным типом.

## Формат проекта

- `.tiasclproj` format 2 добавляет `CallSheet.Groups` и `DiagramGroup` со стабильным GUID,
  `ParentGroupId`, абсолютной геометрией и списком только прямых `MemberNodeIds`.
- Format 3 добавляет `PlantProject.CpuFamily`, необходимый для детерминированной проверки
  диапазонов `%I`/`%Q`/`%M` после открытия файла и при Undo/Redo.
- Текущий reader принимает formats 1, 2 и 3; старые файлы без `Groups` нормализуются в
  пустой список, а без CPU-профиля — в `Unknown`. Writer всегда сохраняет format 3.
- Сборка, поддерживающая только старый формат, отклонит более новый файл до редактирования. Это
  намеренный fail-closed барьер против downgrade, который иначе потерял бы области.
- GUID областей входит в общий project-wide identity registry. Геометрия обязана быть
  конечной, положительной и полностью находиться внутри листа; один узел имеет не более
  одного непосредственного владельца, а циклы родителей запрещены.

## Адреса PLC-тегов и аппаратный каталог

- `Core.PlcAddressing` является единым правилом для создания, редактирования, проверки
  проекта и online-экспорта. Он формирует канонические `I/Q/IW/QW/ID/QD/M/MW/MD`
  адреса и проверяет ширину значения и пределы S7-1200/S7-1500.
- `Openness` возвращает только version-neutral DTO. Legacy V17-адаптер читает точные
  `ChannelAddress` и `ChannelWidth` через `AddressController`; адрес по номеру канала не
  угадывается. Неподдерживаемый или неполный канал пропускается с диагностикой.
- Online-диалог получает свежий каталог до открытия и повторно читает его перед commit.
  Для `I/Q` требуется точное совпадение адреса и типа с актуальным каналом; `M` не является
  аппаратным каналом и остаётся ручным, но требует того же распознанного CPU и проверки
  диапазона. Потеря сессии, смена CPU или канала блокирует изменение атомарно.

## Read-only чтение библиотеки из TIA

- `ITiaGateway.ReadLibrarySnapshot(CancellationToken)` возвращает только version-neutral DTO:
  вид объекта, имя, путь группы, язык и текст источника. Siemens-типы не покидают legacy-адаптер.
- Legacy V17-адаптер рекурсивно читает корневые группы PLC и обычные Software Units. Для
  каждого SCL FB/FC и `PlcStruct` он вызывает
  `PlcExternalSourceSystemGroup.GenerateSource(..., GenerateOptions.None)` в новый ещё не
  существующий файл `.scl`/`.udt` во временной папке. Метод создаёт только внешний файл и
  не добавляет объект в `ExternalSourceGroup`, поэтому состояние проекта TIA не меняется.
- Know-how protected и non-SCL блоки не подменяются SimaticML и не выдаются как успешно
  прочитанные: они дают warning и `IsComplete=false`. Ошибка объекта, конфликт коротких имён
  между Software Units, отмена и пределы объёма также отражаются явно.
- Отменённый, недоступный или пустой снимок не доходит до импорта. Неполный снимок требует
  отдельного подтверждения с отрицательным ответом по умолчанию. После этого используется тот
  же declaration-only parser и план конфликтов, что для файла `.scl`; применение локальной
  библиотеки является одной операцией Undo/Redo, тела FB/FC отбрасываются.
- Ограничения v1: Safety Units V18+ не видны через типизированный façade V17; PLC должен быть
  offline; единый UI-preview ограничен 8 МиБ. Для больших библиотек нужен пакетный parser/preview.
- Реальная сборка против V20 PublicAPI V17 и offline/stub тесты пройдены. Live readback нужно
  отдельно проверить на V20, затем на V17/V18/V19: nested groups, UDT, ordinary Software Unit,
  protected и LAD/FBD skip, коллизии, cancel, online PLC и превышение лимита.

## Безопасность выгрузки

- Локальная валидация выполняется до обращения к TIA; TIA dry-run только читает состояние.
- Подключение к TIA не происходит автоматически при запуске.
- Успешный dry-run выдаёт одноразовый token, привязанный к запросу, байтам исходников,
  выбранному Portal/проекту/PLC и плану коллизий.
- Перед мутацией состояние повторно проверяется уже под `ExclusiveAccess`; устаревший token
  отклоняется. Теги и генерация источников входят в одну `Transaction`.
- OB1 не изменяется.
- Неизвестные существующие блоки нельзя перезаписывать; для своих блоков нужен совпадающий
  `FAMILY` marker, opt-in-флаг и отдельное подтверждение. Существующие UDT пока не
  перезаписываются, потому что API V17 не даёт надёжного marker владения типом.
- Теги создаются до импорта исходников.
- Источники импортируются в порядке: UDT → FB/FC → instance DB → call block → call-block DB.
- Генерация использует `GenerateBlockOption.None`: ошибка не оставляет частично созданные
  блоки. Компиляция и явное сохранение запускаются после выхода из `ExclusiveAccess`.
- Save, обновление тегов и перезапись своих блоков по умолчанию выключены.
- Для фактически headless Portal изменяющий dry-run требует Save. После ошибки
  compile/save dirty-сессия не освобождается молча, а UI предупреждает о риске потери
  данных при закрытии.
- `NonRecoverableException` немедленно инвалидирует все Siemens proxy без повторных
  API-вызовов; `EngineeringSecurityException` возвращается отдельной диагностикой доступа.
- Все `.scl` записываются в UTF-8 с BOM.
