# TIA SCL Studio

Визуальное Windows-приложение (C# / WPF) для сборки программы ПЛК из готовых типовых блоков
и выгрузки результата в проект **TIA Portal V17–V20** в виде SCL — через TIA Portal Openness.

Идея в одну строку: **библиотека готовых FB/FC → своё описание входов и выходов →
графический редактор вызовов → SCL в проекте TIA.**

> Текущий milestone — рабочий визуальный MVP и первый legacy Openness-адаптер:
> редактор библиотеки и схемы → валидация → SCL → обязательный dry-run → подтверждение →
> транзакционная выгрузка. Приложение не подключается к TIA и ничего не изменяет
> автоматически.

## 1. Что делает приложение

Рабочий процесс разделён на четыре этапа, собранных в одном основном окне и диалогах
редактирования.

### Шаг 1. Библиотека блоков

Список готовых типовых блоков — FB (клапан, насос, привод, ПИД-контур) и FC
(масштабирование, пересчёт, диагностика). Блок в библиотеке — это шаблон, который
можно много раз положить на схему.

Блоки берутся из двух источников:

* созданы в самом приложении (интерфейс + тело на SCL);
* импортированы из файла внешнего источника `.scl`: приложение безопасно читает объявления
  и интерфейсы FB/FC/UDT, но не копирует и не выполняет код между `BEGIN` и `END_*`.

Прямое чтение интерфейсов из уже открытого проекта TIA — следующий отдельный этап.

Пользовательские типы данных создаются в отдельной библиотеке UDT. Поля UDT могут
ссылаться на базовые типы или на другие UDT; циклические зависимости блокируются, а
источники генерируются в порядке зависимостей.

### Шаг 2. Редактор интерфейса блока

Здесь вы **сами задаёте и описываете входы и выходы**: таблица переменных с секцией
(`Input`, `Output`, `InOut`, `Static`, `Temp`, `Constant`), типом данных, начальным значением
и комментарием. Плюс редактор тела блока на SCL.

Тип выбирается из закрытого списка базовых типов TIA и объявленных UDT. Существующий
корректный составной тип (`String[n]`, `WString[n]`, `Array[...] of ...`) также сохраняется
в списке. Произвольная строка или ссылка на отсутствующий UDT больше не принимается.

Именно этот интерфейс потом превращается в пины блока на схеме: входы — слева, выходы — справа.

### Шаг 3. Визуальный редактор вызовов — ядро приложения

Лист (канва), на который перетаскиваются блоки из библиотеки. Каждый экземпляр блока —
прямоугольник с именем, типом и пинами. Связи рисуются мышью: тянем от выходного пина
к входному, получаем провод.

Что можно положить на лист:

| Элемент | Назначение | Во что превращается в SCL |
|---|---|---|
| Экземпляр FB | вызов типового блока с экземплярным DB | `"V01"(Open := …, Q => …);` |
| Экземпляр FC | вызов функции | `#tmp := "FC_Scale"(Raw := …);` |
| Терминал тега | вход/выход ПЛК или переменная памяти | `"V01_Open_Cmd"` |
| Константа | литерал | `T#3s`, `TRUE`, `27648` |
| Элемент логики | AND / OR / NOT / компаратор | выражение прямо в аргументе вызова |
| Комментарий-заметка | пояснение на листе | комментарий в коде |
| Визуальная область | группировка участка, линии или агрегата | не влияет на SCL |

Правила редактора:

* пин соединяется только с совместимым по типу — несовпадение типов подсвечивается сразу,
  не дожидаясь компиляции в TIA;
* незаполненный вход берёт значение по умолчанию из интерфейса блока;
* `InOut` обязателен к подключению — редактор не даст сгенерировать код без него;
* один выход можно развести на несколько входов, вход принимает ровно один провод;
* группы и вложенность: лист можно разбить на области (участок, линия, агрегат).

### Шаг 4. Конвертация в SCL и выгрузка в TIA

Схема превращается в текст SCL, тот записывается во внешние источники проекта TIA,
из них генерируются блоки, и запускается компиляция. Ошибки компилятора возвращаются
в приложение и показываются списком.

## 2. Как схема превращается в SCL

Порядок вызовов определяется **топологической сортировкой графа**: блок вызывается после
того, как посчитаны все блоки, чьи выходы к нему приходят. Пользователю не нужно
руками расставлять номера — но порядок можно зафиксировать вручную, если нужно.

Схема из двух блоков:

```
[ V01_Open_Cmd ]──┐
                  ├──▶( Open )┌──────────────┐( Q )──▶[ V01_Sol ]
[ V01_FB_Opened ]─┴──▶(FbOpened)  FB_Valve   │(Fault)─▶[ V01_Fault ]
                     ( TravelTime )◀── T#3s  │
                                  └──────────┘
```

даёт на выходе:

```scl
FUNCTION "FC_CallUnits" : Void
{ S7_Optimized_Access := 'TRUE' }
VERSION : 0.1
BEGIN
   // ---- V01 : FB_Valve — Клапан подачи ----
   "V01"(Open := "V01_Open_Cmd",
         FbOpened := "V01_FB_Opened",
         TravelTime := T#3s,
         Q => "V01_Sol",
         Fault => "V01_Fault");
END_FUNCTION
```

Правила преобразования:

* **входы** подключаются через `:=`, **выходы** — через `=>`;
* экземпляр FB — либо глобальный экземплярный DB (`"V01"`), либо мультиэкземпляр внутри
  блока вызовов (`#V01`); во втором случае блок вызовов сам становится FB и получает свой DB;
* **промежуточное значение** между блоками (выход A → вход B, без тега) кладётся
  во временную переменную `VAR_TEMP` блока вызовов;
* **логика на связи** (AND/OR/NOT/сравнение) собирается в выражение прямо в аргументе:
  `Open := "Cmd_Open" AND NOT "Alarm"`;
* **цикл в графе** (выход блока приходит на его же вход через цепочку) — редактор
  сообщает о нём и предлагает разорвать через статическую переменную предыдущего цикла;
* FC с возвратом вызывается в присваивание, FC типа `Void` — отдельной строкой.

Связывание символов делает сам TIA при генерации блоков из внешнего источника —
приложение не собирает SimaticML-XML руками, и в этом ключевое упрощение.

На текущей машине выполнен один ручной live smoke на тестовом проекте TIA Portal V20
Update 4. Подтверждены attach к уже запущенному Portal, read-only dry-run, одноразовый

Этот результат относится только к одной локальной конфигурации V20 Update 4 и не является
сертификацией всего диапазона V17–V20. Ещё нужно проверить:

* ручной Save проекта, закрытие и повторное открытие `.ap20`;
* повторную выгрузку с подтверждением перезаписи собственных блоков;
* readback созданной таблицы тегов и её содержимого;
* отдельные live-прогоны на V17, V18 и V19.

Приложение сразу открывает рабочую демонстрационную схему `FB_Valve`: блок можно изменить
двойным кликом в библиотеке, перетащить на лист, настроить свойства экземпляра, двигать и
удалять узлы и провода, отменять/повторять изменения и менять масштаб. Можно создавать,
переименовывать и удалять листы, панорамировать холст, выделять рамкой несколько узлов,
добавлять AND/OR/NOT/сравнения, заметки, PLC-теги и константы. Выбранные узлы можно собрать
во вложенную визуальную область, перемещать вместе и затем расформировать без удаления
узлов и проводов. Провод создаётся кликами по выходному и входному пину, занятый вход не
перезаписывается молча, а справа в реальном времени показывается SCL активного листа.
Локальная проверка и онлайн-пакет охватывают весь проект; схема сохраняется и снова
открывается.

## 4. Графический редактор

**Модель схемы** реализована в `TiaSclStudio.Diagram` без зависимостей от WPF:

```
CallSheet          лист: список узлов, список связей, размер, масштаб
  DiagramGroup     визуальная область: parent, прямые участники, геометрия
  CallNode         узел: Id, X, Y, тип (BlockCall | Tag | Const | Logic | Note)
    BlockCallNode  ссылка на BlockDefinition + имя экземпляра + мультиэкземпляр
    TagNode        ссылка на TagDefinition, направление (вход/выход листа)
    ConstNode      литерал и его тип
    LogicNode      операция AND/OR/NOT/>/</=, число входов
  Pin              имя, направление, тип данных, принадлежность узлу
  Wire             (узел-источник, пин) → (узел-приёмник, пин)
```

**Отрисовка MVP** — узлы находятся на `Canvas`, провода рисуются `Path` с кубической
кривой Безье; концы пересчитываются при движении узла.

Тип узла читается не только по подписи, но и по форме и цвету: FB имеет синюю квадратную
метку `FB | STATE`, FC — фиолетовую скруглённую `FC | FUNC`, логика — зелёную, заметки и
константы — янтарную. Терминалы PLC-тегов и константы сделаны компактными (154×44 и
128×44 пикселя); направление тега показано стрелкой, без крупных надписей
`TAG SOURCE`/`TAG SINK`.

Для больших схем есть **«Всё»** (`Ctrl+0`) и **«Выбор»** (`Ctrl+Shift+0`): редактор
вычисляет реальные границы узлов/областей, уменьшает масштаб до 15% и центрирует обзор.
Обычный диапазон масштабирования — 15–200%. Команда **«Авто»** (`Ctrl+L`) раскладывает
активный лист слева направо: источники и константы → логика → FB/FC → выходные теги.
Внутри слоёв выполняется детерминированное сокращение пересечений проводов, плотные слои
переносятся в соседние колонки, а циклические и полностью неподключённые узлы попадают в
отдельную нижнюю зону. Вложенные области сохраняют состав и получают новые рамки вокруг
участников; пустые области переносятся отдельно. Лист расширяется до безопасного предела
50 000×50 000. Раскладка является одной операцией Undo/Redo, после неё автоматически
выполняется «Показать всё». Узлы, пины, провода и итоговый пакет SCL не изменяются; прежний
порядок независимых вызовов фиксируется перед перемещением.

Новые узлы по-прежнему ищут ближайшее свободное место, а лист при необходимости
расширяется; добавление и расширение входят в одну операцию Undo/Redo.

**Уже работает** — навигация и CRUD нескольких листов, drag-and-drop блока из библиотеки,
перетаскивание и свойства узлов, создание провода кликами по пинам, рамочное выделение и
групповое удаление, pan, проверка направления и типа, защита занятого входа, Undo/Redo,
масштаб, auto-layout, заметки, логические узлы, прямое создание терминалов новых/существующих PLC-тегов
и констант, вложенные визуальные области, диагностика всего проекта и предпросмотр SCL
активного листа. Онлайн-выгрузка собирает общий dependency-ordered пакет всех листов и
блокируется при ошибке на любом из них.

**Следующий UI-срез** — инспектор проекта, изменение размеров областей и чтение интерфейсов
существующих блоков напрямую из подключённого проекта TIA.

**Преобразование графа в код** — топологическая сортировка (алгоритм Кана), обнаружение
циклов, распределение временных переменных и свёртка логических узлов в полностью
скобочные выражения реализованы отдельно от UI и покрыты офлайн-прогоном. Fan-out
вычисляет выражение один раз; прямой выход логики в тег генерирует присваивание даже на
листе без вызовов FB/FC.

**Сериализация** — координаты, связи, вложенные области и выбранное семейство CPU
сохраняются в файл модели (`.tiasclproj`). Текущий writer использует формат 3; reader
принимает форматы 1, 2 и 3. Форматы 1/2 загружаются с неизвестным семейством CPU и
переходят на формат 3 при успешном сохранении. Старая сборка отклонит новый файл и не
сможет молча удалить новые данные при повторном сохранении.

**PLC-адреса** — при создании и редактировании тега выбираются S7-1200/S7-1500,
`DI`/`DO`/`AI`/`AO`/`M` и совместимый тип. Адрес формируется канонически (`%I0.0`,
`%Q0.0`, `%IW64`, `%QW64`, `%ID64`, `%QD64`, `%M0.0`, `%MW0`, `%MD0`) и проверяется
по диапазону CPU. При активном подключении к TIA аппаратные I/O выбираются только из
свежего read-only каталога реально сконфигурированных каналов; каталог повторно читается
перед фиксацией изменения. Область `M` остаётся ручной, но проверяется по фактическому
семейству CPU. Если каталог, CPU или TIA-сессия изменились, операция завершается без
изменения модели.

### Импорт библиотеки из SCL

Команда **`SCL · Импорт FB / FC / UDT`** читает один внешний исходник с несколькими
объявлениями и показывает план до изменения проекта. Поддерживаются интерфейсные секции
FB/FC, возвращаемый тип FC, версия, `S7_Optimized_Access`, объявления `TYPE ... STRUCT`,
массивы и строки фиксированной длины. UDT из того же файла можно объявить до или после
использующего его блока.

Импорт намеренно работает только с декларациями: тело FB/FC не переносится и импортированный
блок получает признак `ImportedInterfaceOnly`. Поэтому такой блок предназначен для вызова
уже существующей реализации в TIA. Неподдерживаемая или неоднозначная конструкция, неизвестный
тип, цикл UDT либо глобальный конфликт имени блокируют весь пакет без частичных изменений.
Одноимённые объекты по умолчанию пропускаются; их обновление нужно включить явно в окне
предпросмотра. Применение всего пакета является одной операцией Undo/Redo.

Текущий безопасный subset явно отклоняет inline/анонимные `STRUCT`, alias/enum, `AT`,
неизвестные `VAR_*`, расширенные системные типы и статические multi-instance объявления
вида `VAR Child : "FB_Child"`; они не пропускаются молча как якобы успешно импортированные.

## 5. Требования к машине

* Windows x64 и .NET Framework 4.8.
* Для сборки — .NET Framework 4.8 Developer/Targeting Pack и инструменты WPF из
  Visual Studio 2019/2022 или Build Tools.
* Для онлайн-выгрузки — TIA Portal **V17–V20** (STEP 7 Professional) и компонент
  **TIA Portal Openness** на той же машине.
* Пользователь Windows — член локальной группы **`Siemens TIA Openness`**
  (`lusrmgr.msc` → Группы). После добавления нужно **перелогиниться**.
* При первом подключении TIA Portal покажет запрос безопасности — подтвердить.

Офлайн-редактор и генератор не требуют установленного TIA Portal. Отдельная лицензия на
Openness не нужна, но для реальной выгрузки должен быть установлен соответствующий STEP 7.

`Siemens.Engineering.dll` не загружается из NuGet и не хранится в репозитории. Его ставит
официальный установщик TIA Portal: выберите компонент **TIA Portal Openness**. Например,
Portal V20 содержит совместимый façade V17 по пути
`C:\Program Files\Siemens\Automation\Portal V20\PublicAPI\V17\Siemens.Engineering.dll`.
Наш код адаптера находится в `src/TiaSclStudio.Openness.Legacy.V17`.

Локатор проверяет 64- и 32-битные представления реестра, legacy layout V17–V20 и новый
модульный layout V21+. V21 потребует отдельного адаптера: он больше не поставляет старые
`Siemens.Engineering.dll` V17–V20. Подробности и честная матрица проверки —
в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Почему C#, а не Rust

`Siemens.Engineering.dll` — обычная .NET-сборка под .NET Framework, не COM и не C ABI.
Из Rust её можно достать только подняв CLR в процессе (`netcorehost` умеет .NET Core,
а не Framework — не подходит). Если Rust принципиален: GUI на `egui`/Tauri + отдельный
C#-процесс-воркер, общение по stdin/stdout JSON или named pipe. Но C# вы всё равно
напишете, только добавите протокол между процессами.

## 6. Сборка

```
msbuild TiaSclStudio.sln /m /p:Configuration=Release /p:Platform=x64
```

Проект legacy-адаптера сам ищет официальный API V17 в стандартных каталогах Portal
V17–V20. Для нестандартной установки путь задаётся явно:

```
msbuild TiaSclStudio.sln /m /p:Configuration=Release /p:Platform=x64 /p:TiaOpennessV17AssemblyPath="D:\Siemens\PublicAPI\V17\Siemens.Engineering.dll"
```

Если DLL не найдена, solution всё равно собирается с безопасной offline-заглушкой;
Connect в такой сборке недоступен.

или открыть `TiaSclStudio.sln` в Visual Studio 2019/2022 и собрать `Release | x64`.
При установленном .NET SDK на Windows также работает:

```
dotnet build TiaSclStudio.sln -c Release -p:Platform=x64
```

Проверка генератора **без TIA Portal** после сборки:

```
tools\selftest\bin\Release\TiaSclStudio.SelfTest.exe .\artifacts\selftest
```

Скрытый smoke WPF (окно не показывается, к TIA не подключается) проверяет загрузку ресурсов,
selector листов, палитру Logic/Note и связку добавление Logic → Undo:

```
powershell -STA -ExecutionPolicy Bypass -File tools\wpf-smoke.ps1 -ArtifactDirectory src\TiaSclStudio.App\bin\x64\Release
```

## 7. Структура решения

```
src/TiaSclStudio.Core/        модель + генератор SCL + валидатор.  Ноль зависимостей от TIA.
  Model/                      BlockDefinition, InterfaceMember, UnitDefinition, TagDefinition, PlantProject
  Generation/SclGenerator.cs  модель -> текст SCL (FB, FC, UDT, экземплярные DB, блок вызовов)
  Validation/                 проверки до импорта: типы, дубли, InOut без привязки, коллизии имён
  Storage/                    запись .scl в UTF-8 с BOM

src/TiaSclStudio.Openness/    обнаружение API, DTO и безопасный контракт адаптеров
  OpennessInstallationLocator поиск legacy V17–V20 и modular V21+ без загрузки DLL
  ITiaGateway                 контракт подключения/выгрузки без Siemens-типов
  OfflineGateway              гарантированно не открывает и не изменяет TIA

src/TiaSclStudio.Openness.Legacy.V17/
  LegacyV17Gateway            реальный x64-адаптер Portal V17–V20 на API V17
  SiemensAssemblyResolver     проверенная и привязанная к одной установке загрузка Siemens DLL

src/TiaSclStudio.Diagram/     модель схемы, валидация, топология, SCL и XML `.tiasclproj`
src/TiaSclStudio.App/         WPF: канва, SCL preview, TIA Online, dry-run и подтверждение
tools/selftest/               офлайн-прогон Core + Diagram + запрет экспорта OfflineGateway
```

Граница проведена намеренно: **Core и Diagram тестируются без TIA Portal**, а всё,
что может сломаться от смены версии TIA, заперто в одном проекте.

## 8. Порядок выгрузки в TIA

Генерируемые файлы идут **строго в этом порядке** — файл N ссылается на объекты из файла N−1,
а TIA разрешает символы в момент генерации блоков из исходника:

| Порядок | Файл | Содержимое |
|---|---|---|
| 0 | `00_Types.scl` | UDT (`TYPE ... END_TYPE`) |
| 1 | `<Имя>.scl` | по файлу на каждый FB/FC |
| 2 | `90_Instances.scl` | экземплярные `DATA_BLOCK` |
| 3 | `99_<блок вызовов>.scl` | вызовы всех блоков со схемы |
| 4 | `99z_<...>_DB.scl` | экземпляр блока вызовов, если он получился FB |

Перед изменениями выполняется dry-run: проверяются файлы, UTF-8 BOM, порядок, OB1,
коллизии тегов/блоков/UDT и маркер владения. Успешный план выдаёт одноразовый token;
непосредственно перед транзакцией состояние проверяется повторно под `ExclusiveAccess`.
Теги создаются через API **до** импорта кода. Компиляция выполняется только после завершения
транзакции и освобождения `ExclusiveAccess`; дерево `CompilerResult.Messages` разворачивается
в общую таблицу диагностики.

## 9. Подводные камни

* **Две семьи API.** V17–V20 используют legacy `Siemens.Engineering.dll`; Portal V20
  поставляет API V17–V20 и запускает приложения этих версий. Начиная с V21 API модульный,
  поэтому нужен отдельный адаптер, а не binding redirect.
* **x64 обязателен.** `AnyCPU` с `Prefer 32-bit` даёт `BadImageFormatException`.
* **Одна установка Portal на процесс.** Legacy façade нельзя выгрузить из `AppDomain`.
  После первого реального подключения для смены корня Portal V17/V18/V19/V20 требуется
  перезапуск приложения; адаптер отклоняет небезопасное переключение.
* **Headless Portal.** Любая изменяющая операция в `WithoutUserInterface` требует явно
  включённый Save. Если компиляция или сохранение завершились ошибкой, проект остаётся
  изменённым, повторное подключение блокируется; сначала исправьте ошибку и успешно
  сохраните проект. Завершение приложения в этот момент не гарантирует сохранность
  headless-сессии.
* **Группа `Siemens TIA Openness`** — без неё подключение падает с невнятной ошибкой доступа.
* **Кодировка.** `.scl` пишется в UTF-8 **с BOM**, иначе кириллица в комментариях
  превращается в мусор. Уже сделано в `ProjectStorage.WriteSource`.
* **Целевая группа блоков зависит от версии.** В V17 внешний источник генерирует блоки
  в корень `Program blocks`; более новые API имеют дополнительные overload. Это capability
  конкретного адаптера, а не единое правило для всех версий.
* **Перезапись.** `GenerateBlocksFromSource` перезаписывает блок целиком. Ручные правки
  в TIA будут потеряны: для сгенерированных блоков единственный источник истины — схема.
* **Know-how protected блоки** через Openness недоступны.
* **Скорость.** Openness небыстрый. Пакетные операции завёрнуты в `ExclusiveAccess`,
  иначе TIA дёргает UI на каждую операцию. Компиляция в `ExclusiveAccess` **не** заворачивается.
* **OB не трогаем.** Приложение не редактирует OB1 — вызов сгенерированного блока
  добавьте один раз руками. Перезапись OB1 — лучший способ испортить чужой проект.
* **Номера блоков.** При генерации из исходника номера назначает TIA. Нужен конкретный
  номер — только через XML-импорт.

## 10. CI/CD и релизы

GitHub Actions выполняет строгую x64-сборку, все тестовые наборы, offline self-test,
WPF smoke, CodeQL и опциональный SonarQube. Артефакт с hosted runner честно помечен
как `offline-stub`: на стандартной машине GitHub нет лицензированной Siemens PublicAPI.

Production ZIP собирается по тегу `v*` только на доверенном self-hosted Windows runner
с установленным TIA Portal/Openness V17 API. Workflow проверяет наличие настоящего
адаптера, исключает `Siemens.Engineering.dll` из пакета, создаёт SHA-256 и публикует
GitHub Release. Настройка runner, signing secrets и branch protection описаны в
[docs/CI-CD.md](docs/CI-CD.md).
